# e2e

End-to-end тесты на Playwright. Конфиг — [../playwright.config.ts](../playwright.config.ts).

Каталог **не является пакетом монорепы**: своего `project.json` нет, в nx-граф и
в pnpm-воркспейс он не входит. Значит, `nx run-many` его не подхватит, и гонять
надо явными командами из корня репозитория.

```bash
pnpm run e2e                 # прогон
pnpm run e2e -- --headed     # с окном — только если пробросил дисплей
pnpm run e2e:type-check      # tsc по спекам (playwright типы НЕ проверяет)
pnpm run e2e:report          # html-отчёт последнего прогона
pnpm run e2e:install         # доставить браузер, если его нет
```

Приложение под тестами задаётся в конфиге (`webServer`) или через
`E2E_BASE_URL=http://…` перед командой.

## Правила

- **Локаторы — `getByRole` / `getByLabel` / `getByTestId`**, не CSS-классы:
  вёрстку рефакторят, и класс отвалится молча.
- **Никаких `waitForTimeout`.** Ожидание — через веб-первые ассерты
  (`await expect(...).toBeVisible()`), они ретраятся сами.
- **Тест не зависит от других тестов и от их порядка** — файлы гоняются
  параллельно, а в CI ещё и с ретраем.
- Падает через раз — это баг теста, а не окружения. Разбор — в скилле
  `playwright-pro`, `reference/flaky-tests.md`.

Полный свод (локаторы, фикстуры, ассерты, миграция с Cypress/Selenium) — в скилле
[playwright-pro](../.claude/skills/playwright-pro/SKILL.md), он раздаётся платформой.

## Не путать с браузерным MCP

Здесь — тесты, которые гоняет CI. Отдельно от них у агентов есть **браузер как
инструмент** (MCP-сервер `playwright`): открыть страницу, потыкать, снять
скриншот, прочитать консоль — вживую, без написания спеки. Им удобно
_разведывать_ поведение приложения; результат разведки оформляется тестом сюда.
Выхлоп MCP падает в `.playwright-mcp/` (в гите его нет).
