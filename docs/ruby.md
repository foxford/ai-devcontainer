# Ruby-проекты в ADC

ADC поставляет `asdf`, плагин `asdf-ruby` и системные зависимости для сборки Ruby и гемов с нативными расширениями. Нужную версию Ruby устанавливают отдельно по настройкам проекта. Подключение репозитория не выполняет его `Dockerfile`, `.devcontainer` или `bundle install`.

## Обновить среду

Для существующей установки выполните на хосте полное обновление:

```sh
adc update
```

Обновление пересобирает образ и перезапускает работающий workspace, завершая его процессы. Если среда была остановлена, запустите её через `adc workspace start`. Команды `adc update --delivery` недостаточно: она обновляет доставляемые файлы, но не добавляет системные пакеты и `asdf` в образ.

Бинарник `asdf` находится в `/usr/local/bin`; версия и контрольные суммы вместе с ревизией плагина записаны в [runtime/asdf-lock.json](../runtime/asdf-lock.json). При запуске ADC добавляет закреплённый плагин Ruby в `/home/node/.asdf/plugins/ruby`, если плагина ещё нет. Существующий плагин, установленные версии и пользовательские настройки сохраняются. ADC не выбирает общую версию Ruby для всех проектов и не запускает его сборку при старте workspace.

Если раньше вы вручную настраивали asdf `0.15` или старше, проверьте свои `.bashrc` и `.zshrc`: уберите старую инициализацию `. "$HOME/.asdf/asdf.sh"` и ручное добавление `~/.asdf/bin` в `PATH`. Откройте новый терминал и проверьте `command -v asdf`: ожидается `/usr/local/bin/asdf`. Затем выполните `asdf reshim ruby`, чтобы старые shims использовали новый бинарник. Каталог `~/.asdf` с установленными версиями и гемами оставьте на месте. Подробности — в [руководстве перехода на современный asdf](https://asdf-vm.com/guide/upgrading-to-v0-16.html).

## Установить Ruby проекта

Откройте терминал внутри ADC или Orca и перейдите в корень подключённого проекта. Если в `.tool-versions` уже указана версия Ruby, выполните:

```sh
asdf --version
asdf install ruby
asdf current ruby
ruby --version
```

`asdf install ruby` читает версию из `.tool-versions` и устанавливает только Ruby. Команда `asdf install` без имени инструмента пытается установить всё из этого файла. Например, в stoege зафиксированы `ruby 3.4.13` и `nodejs 24.18.0`; Node.js уже поставляется образом ADC, поэтому для подготовки Ruby не нужно устанавливать его повторно через asdf.

Первая установка Ruby скачивает исходники и компилирует их, поэтому требует сети и времени. Версии, shims и гемы, установленные в `/home/node/.asdf`, сохраняются в томе home после пересоздания контейнера. Настройка Bundler `path`, если она есть в проекте, определяет отдельное место установки гемов.

Для проекта только с `.ruby-version` согласуйте добавление `.tool-versions` по правилам этого репозитория. Например, для Ruby `3.4.13`:

```sh
asdf install ruby 3.4.13
asdf set ruby 3.4.13
```

`asdf set` создаёт или изменяет `.tool-versions` в текущем каталоге; замените версию на указанную проектом. В современной версии asdf используются команды `set`, а прежние `asdf local` и `asdf global` удалены. Подробности выбора версии — в [документации asdf](https://asdf-vm.com/manage/versions.html).

## Установить гемы

Возьмите версию Bundler из раздела `BUNDLED WITH` в `Gemfile.lock`. Например, для stoege с Bundler `2.6.9`:

```sh
gem install bundler -v 2.6.9
asdf reshim ruby
bundle _2.6.9_ install
```

После установки новых исполняемых файлов через `gem install` команда [`asdf reshim ruby`](https://asdf-vm.com/manage/core.html#reshim) обновляет shims, чтобы команды стали доступны в `PATH`. Устанавливайте гемы от обычного пользователя ADC без `sudo`.

Если `Gemfile` содержит приватные Git-источники, до `bundle install` настройте доступ к ним внутри среды. Авторизация на хосте автоматически не передаётся; порядок работы описан в разделе [Git и приватные зависимости](workspace.md#git-и-приватные-зависимости). Полная установка зависимостей stoege требует этого доступа отдельно от Ruby и системных библиотек.

## Системные зависимости и сервисы

Набор системных пакетов задаётся в [runtime/Dockerfile](../runtime/Dockerfile). Для Ruby и нативных гемов в него входят:

| Назначение | Пакеты |
|---|---|
| Компиляция Ruby и расширений | `build-essential`, `make`, `pkg-config`, `autoconf`, `libssl-dev`, `libyaml-dev`, `zlib1g-dev`, `libffi-dev`, `libgmp-dev` |
| Гемы с дополнительными библиотеками | `cmake`, `libpq-dev`, `libclang-dev`, `libgit2-dev`, `libzstd-dev` |
| Обработка изображений | `imagemagick` |

Этот набор не означает поддержку всех возможных гемов. Если проекту нужен ещё один системный пакет, его нужно добавить в `runtime/Dockerfile` и пересобрать образ. Ручная установка через `apt` внутри работающего контейнера теряется при его пересоздании. Каталога `bin/bootstrap-lib/asdf` в текущем ADC нет.

`libpq-dev` предоставляет библиотеку и заголовки PostgreSQL для сборки гемов; сервер PostgreSQL этим не запускается. Базы данных, Redis, переменные окружения и остальные сервисы настраиваются по документации проекта отдельно. ADC не поднимает окружение из проектного Dockerfile автоматически.

Дев-серверы запускаются обычными командами проекта в терминале ADC или Orca; агент может запускать и останавливать их в пределах поручения и правил репозитория. Для браузера на хосте опубликуйте порт и привяжите сервер к `0.0.0.0`. Штатному браузеру Chrome DevTools MCP внутри ADC публикация не нужна. Пример для порта `3333` и условия пересоздания контейнера описаны в разделе [Порты сервисов](workspace.md#порты-сервисов).
