# Переход с v0 на общий ADC

Результат — один общий контейнер ADC для всех подключённых проектов. Старые devcontainer служат источниками данных для миграции и остаются остановленными. Миграция копирует данные в новые тома; исходные каталоги, контейнеры и тома не удаляются.

Все команды выполняйте на хосте; в WSL — внутри того дистрибутива, где работал старый ADC. Следующий шаг выполняйте только после успешного завершения предыдущего. Имена контейнеров и ID профиля в примерах замените своими.

## 1. Остановить старую среду

Сохраните работу в редакторе, завершите сессии агентов и посмотрите имена старых контейнеров:

```sh
docker ps -a --filter label=devcontainer.local_folder --format '{{.Names}}'
docker stop old-container
```

Остановите все контейнеры, использующие старую платформу или общий том инструментов. Контейнеры и тома не удаляйте.

## 2. Заменить установленный ADC

Получите исправленный updater из v0 в обычный каталог установки:

```sh
git -C "$HOME/.local/share/ai-devcontainer" fetch origin v0 &&
git -C "$HOME/.local/share/ai-devcontainer" switch --detach FETCH_HEAD
```

После успешного переключения:

```sh
adc update --branch main
```

Установка сохранит копию старой платформы, заменит ADC в PATH и настроит completion. Дополнительный каталог установки не нужен. Откройте новый терминал. Старые devcontainer пока не запускайте и не пересоздавайте; проекты через adc project add пока не добавляйте.

## 3. Проверить проекты и состав старой среды

Проверка проекта не изменяет файлы и доступна до регистрации:

```sh
adc doctor project /path/to/repository
```

Укажите старые контейнеры отдельными флагами --container. План нужен для определения хостовых путей проектов и профилей; создание плана ничего не копирует.

```sh
adc migrate legacy plan --container old-container --output "$HOME/adc-migration-plan.json"
```

## 4. Подключить проекты и перенести профили

Выберите профиль, чьи аккаунты и настройки станут общими. Его ID записан в containers[].project плана. В примере — repo-3dboardgame:

```sh
adc migrate legacy import-host "$HOME/adc-migration-plan.json" --account repo-3dboardgame --workspace developer-v1 &&
adc workspace start
```

Репозитории остаются на хосте и подключаются bind-маунтами. Команда копирует только примонтированные профили агентов и общий MCP/Hermes store в новые тома. Остальные профили сохраняются отдельно; совместимые истории объединяются без перезаписи конфликтов. Оригиналы, старые контейнеры и тома остаются на месте. Проверенная копия выбранных профилей сохраняется в ~/.adc/backups/profiles; отдельные backup и verify не нужны.

Кеши, проектные DinD-тома и файлы, оставшиеся только в writable layer старого контейнера, этот путь не переносит. Если агенты хранили данные внутри контейнера без маунта, используйте полный backup/import из [справки](migration-reference.md). Старые DinD-тома сохраняйте, пока не перенесли данные проектных сервисов.

Проверьте вход в агенты, старые сессии, MCP и Obsidian. Первый запуск скопирует служебное состояние проекта из .ai-devcontainer в .adc, проверив SHA-256; старый каталог остаётся до очистки. Если оба каталога появились независимо, ADC остановится вместо объединения наугад. Проектные правила и конфиги в .agents сохраняются.

## 5. Убрать проектный devcontainer и сбросить старую доставку

После проверки новой среды остановите её и посмотрите план очистки нужного проекта:

```sh
adc workspace stop
adc migrate legacy cleanup <project-id> --devcontainer
```

Если список подходит, примените очистку и восстановите доставку в общей среде:

```sh
adc migrate legacy cleanup <project-id> --devcontainer --apply &&
adc workspace start &&
adc sync <project-id>
```

Перед удалением команда сохраняет и проверяет копию в ~/.adc/backups/project-cleanup. Исходники, проектные правила, .agents конфиги и форки, личные настройки агентов и новое состояние .adc сохраняются. Неподтверждённые файлы выводятся как «Оставить».

Состав копии, установка на Windows, восстановление после прерывания и возврат к v0 — в [справке](migration-reference.md).
