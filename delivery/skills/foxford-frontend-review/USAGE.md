# Установка и использование

Установка из локального checkout ADC, содержащего эту версию:

```sh
npx skills add <adc-checkout>/delivery/skills/foxford-frontend-review --agent claude-code codex --copy --yes
```

Выполняйте команду из нужного проекта. Для изолированной проверки сначала создайте временный пустой каталог и перейдите в него. `--copy` доставляет соседние CODESTYLE.md, USAGE.md и meta.json вместе с SKILL.md, без зависимости от исходного checkout. Установку проверяйте через `npx skills list --json`, наличие файлов и доступность относительных ссылок. Глобальная установка здесь не требуется.

После публикации ветки с этим skill в командном репозитории:

```sh
npx skills add foxford/ai-devcontainer --skill foxford-frontend-review --agent claude-code codex --copy --yes
```

Команда без ref использует опубликованную ветку по умолчанию. Для другой опубликованной ветки укажите URL `https://github.com/foxford/ai-devcontainer/tree/<branch>/delivery/skills/foxford-frontend-review`. До публикации проверяется локальная установка; она не доказывает доступность неопубликованной версии через GitHub.

Примеры явного обращения к установленному skill:

```text
$foxford-frontend-review Проверь и исправь изменения тикета от <base-sha>, включая staged, unstaged и новый client/Card.css. user-notes.css — отдельная пользовательская работа.

$foxford-frontend-review Без изменений: проверь frontend-часть PR от <base-sha> и рабочий результат. Верни замечания со ссылками на правила.
```

В Claude Code используйте `/foxford-frontend-review` с тем же поручением. После установки откройте новую сессию, если агент ещё не обновил каталог skills. Из другого workflow передавайте базу, состав задачи и режим; установщик не подключает skill к implement автоматически.

## Оценка изменений skill

Эта версия охватывает CSS, организацию React-компонентов, публичные импорты, локализацию JSX и границу UI-kit. При изменении инструкций запускайте установленную копию на небольшом Git-проекте с доступными проверками и сохраняйте исходное дерево, конечный diff, отчёт агента, команды и ограничения. Оценка поведения агентом не является детерминированным CSS-линтером.

Проверьте нарушение и допустимую пару каждого правила, намеренные дробные px, коэффициенты, проценты, углы, global/reset и scoped rich text. Отдельно проверьте документированное исключение проекта и похожий legacy-код без такого документа. Включите релевантный коммит, staged/unstaged изменения, новый файл, пользовательскую правку вне задачи и соседний legacy-участок. Сравните защищённые файлы и индекс до и после.

Повторите пример в режиме без изменений и сравните все рабочие файлы. Оцените backend-only, смешанный diff, серверный .ts со строками CSS и недостаточный контекст области. Backend-only должен дать «неприменимо», смешанный — проверку только подходящих участков, недостаточный контекст — неполную проверку. У каждого нарушения нужны место, ссылка и исправление либо предложение; исключения и фактические результаты проверок должны присутствовать в отчёте. После исправления повторите правила и профильные проверки проекта.

Для React, импортов и i18n проверьте пары и исключения каждого раздела CODESTYLE.md. Сохраните исходники и результат; после автоматических исправлений проверьте поведение, указанное в соответствующем правиле. Включите неоднозначный перенос с hooks, опасный barrel с циклом или side effects и проект без FormattedMessage: ожидаются предложения либо неприменимость, без механической миграции.

Для UI-kit включите внутренний класс, тег и структурный селектор (в том числе внутри rich text), публичные props/variant/theme и внешнюю layout-обёртку. Подтвердите контракт используемой версии; наличие className само по себе недостаточно. Проверьте небольшое отличие от макета: ожидается конкретный запрос решения со штатным вариантом, без принятого отклонения и завершения зависимой части. Отдельно оцените уже согласованное отклонение и неизвестные измерения. Установка не обеспечивает остановку существующего runner; интеграция с очередью остаётся отдельной задачей.
