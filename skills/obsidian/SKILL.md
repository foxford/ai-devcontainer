# Obsidian

Два независимых механизма. Первый работает всегда и без вопросов. Второй —
MCP-сервер, который может быть не подключён, и это нормально.

## Когда использовать

- Пользователь просит сохранить заметку, решение, сводку сессии, план или
  ресёрч **в Obsidian** («запиши в obsidian», «сохрани заметку», «занеси в
  vault»).
- Пользователь просит **найти, прочитать или обновить** что-то в его
  Obsidian-vault'е.
- Пользователь просит собрать код-граф проекта как vault — это `graphify
  --obsidian`, отдельный флаг соседнего скилла `/graphify`, не этот скилл
  сам по себе (см. «Отношение к graphify» ниже).

**Не использовать** как способ просто «записать markdown-файл» — если
пользователь не упомянул Obsidian/vault явно, обычный файл в репозитории
(или `plans/`, если это задача) уместнее: vault — это его личное
пространство, туда не стоит сваливать то, о чём не просили.

## Vault-каталог (работает всегда, файловый)

Персист-маунт `/home/node/obsidian-vault` есть в каждом проекте с рождения
(`~/.ai-devcontainer-dev/<проект>/obsidian` на хосте) — писать туда `.md`
можно прямо сейчас, без проверок и настройки:

```bash
cat > /home/node/obsidian-vault/2026-08-31-decision.md <<'EOF'
# Почему выбрали X вместо Y
...
EOF
```

Это ОТДЕЛЬНЫЙ, посвящённый проекту vault — не обязательно тот, что открыт у
пользователя в Obsidian по умолчанию. Формат — обычный Obsidian:
`[[wikilinks]]` на другие заметки в этом же vault'е работают. Ссылки на файлы
репозитория — обычными относительными markdown-путями, `[[...]]` для них не
годится.

## MCP-сервер `obsidian` (опционально, живой доступ к ЛЮБОМУ vault'у)

Если сервер `obsidian` есть в списке доступных инструментов — он даёт живой
доступ к тому vault'у, который у пользователя реально открыт в Obsidian на
хосте (не обязательно к vault-каталогу выше). Сервера может не быть: он
включается на хосте отдельно (`README.md, раздел «Obsidian»` в репозитории
платформы) и раздаётся, только когда настроен ключ. Если инструментов
`vault_*`/`search_*`/`tag_list` нет в списке — просто скажи пользователю
одной строкой, что сервер не подключён, сославшись на `README.md, раздел «Obsidian»`,
и не блокируйся на этом: то, что выполнимо через vault-каталог выше, всё
равно выполнимо.

Основные инструменты (точные названия могут отличаться версией плагина):

| Инструмент | Что делает |
|---|---|
| `vault_list` | список файлов/подкаталогов vault'а |
| `vault_read` | прочитать файл — контент, frontmatter, теги |
| `vault_write` | создать или перезаписать файл |
| `vault_append` | дописать в конец файла |
| `vault_patch` | точечно поправить заголовок/блок/поле frontmatter |
| `vault_delete` / `vault_move` / `vault_copy` | удалить / переименовать / скопировать |
| `vault_get_document_map` | заголовки, блок-ссылки, frontmatter файла |
| `search_simple` | полнотекстовый поиск (встроенный поиск Obsidian) |
| `search_query` | поиск по метаданным через JsonLogic |
| `tag_list` | все теги vault'а со счётчиками |
| `command_list` / `command_execute` | список / выполнение команд Obsidian |
| `active_file_get_path` | путь файла, открытого в Obsidian прямо сейчас |
| `open_file` | открыть файл в UI Obsidian |

## Отношение к graphify

`graphify --obsidian --obsidian-dir /home/node/obsidian-vault` — способ
АВТОМАТИЧЕСКИ наполнить vault-каталог граф-представлением кода (по одному
файлу на узел графа). Это отдельная, самостоятельная функциональность
соседнего скилла `/graphify`, не обязательная часть этого скилла: можно
писать заметки в vault вообще не трогая graphify, и можно гонять graphify без
единой ручной заметки. Смешиваются они только физически — в одном
каталоге, — не логически.
