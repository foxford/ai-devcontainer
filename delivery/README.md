# Что ADC доставляет

Состав поставки описан в [catalog.json](catalog.json). Общие материалы лежат в инструкциях, документах и библиотеке скиллов. Возможности с несколькими частями оформлены бандлами: их декларация и файлы находятся рядом в `bundles/`. Документация самого ADC находится в [docs/](../docs/), движки — в [bin/adc/runtime/](../bin/adc/runtime/).

```text
delivery/
├── catalog.json                  # base, простые возможности, регистрации бандлов
├── instructions/                 # общий контракт и правила простых возможностей
├── documents/                    # документы, доставляемые в проекты
├── skills/                       # общая библиотека скиллов
├── mcp/                          # общие определения MCP и образец секретов
└── bundles/
    ├── graphify/
    │   ├── bundle.json           # декларация exports
    │   ├── instructions.md       # когда и как агент использует граф
    │   ├── graphify/             # полный SKILL.md и references
    │   └── mcp.json              # MCP, обслуживаемый Go-бинарником ADC
    └── obsidian/
        ├── bundle.json           # декларация exports
        ├── instructions.md       # область работы с заметками
        ├── obsidian/SKILL.md      # скилл Obsidian
        └── mcp.json              # подключение к Obsidian на хосте
```

## Каталог и бандлы

Capability — имя, которое выбирает проект через `--capability` или `.agents/project.json`. Bundle — пакет материалов и инструментов, экспортируемый этой возможностью. Простое правило можно объявить прямо в каталоге; связанный набор поставки — через manifest бандла.

Например, каталог регистрирует Graphify так:

```json
{
  "graphify": {
    "bundle": "bundles/graphify/bundle.json"
  }
}
```

[Декларация Graphify](bundles/graphify/bundle.json) описывает, что он поставляет наружу:

```json
{
  "version": 1,
  "name": "graphify",
  "description": "Локальный граф кода: индекс, скилл, CLI и MCP для агентов",
  "exports": {
    "instructions": ["instructions.md"],
    "skills": ["graphify"],
    "documents": [],
    "tools": [
      {
        "command": "graphify",
        "package": "graphifyy",
        "version": "0.9.82",
        "installer": "uv"
      }
    ],
    "mcp": {
      "source": "mcp.json",
      "servers": ["graphify"]
    }
  }
}
```

Пути в `catalog.json` отсчитываются от `delivery/`. Пути источников внутри `exports` отсчитываются от каталога бандла; выходить за него нельзя. `documents.target` всегда относится к корню подключённого проекта. Имя каталога экспортируемого скилла становится его именем в собранном дереве.

| Поле exports | Что доставляется | Кто использует |
|---|---|---|
| `instructions` | Дополнительные правила в AGENTS.platform.md | Агент |
| `skills` | Скиллы, выбранные только для этого проекта; проектные форки сохраняются | Агент |
| `documents` | Файлы с source, target и mode copy/link | Разработчик и агент |
| `mcp.source` + `mcp.servers` | Определения и список экспортируемых MCP | Движок MCP; серверы получают namespace checkout |
| `tools` | Закреплённые CLI-пакеты в общей среде | Установщик runtime |

У Obsidian экспортируются скилл, инструкции и MCP; тулз для установки нет. У Graphify дополнительно устанавливается CLI и автоматически обслуживается индекс. Эти действия принадлежат обработчику Graphify в Go, а версия и состав поставки — декларации. `tools` сейчас поддерживает uv-поставку Graphify; новый тип установщика требует обработчика Go и тестов, произвольные команды из JSON не выполняются.

## Общий слой

| Поле каталога | Назначение |
|---|---|
| `base.instructions` | Контракт всех проектов |
| `base.documents` | Общие документы и образцы |
| `base.skills` | Общая библиотека в skills/ |
| `base.mcp.source` | Общие определения MCP в mcp/servers.json |
| `base.mcp.servers` | Серверы, выбранные для всех проектов; сейчас пусто |
| `capabilities.<name>` | Простая возможность или регистрация bundle |

Определение MCP само по себе не включает сервер. Его выбирает capability; затем `x-requires` проверяет браузер или секрет. Платформенные определения из общих файлов и бандлов составляют нижний слой; пользовательский, проектный и локальный слои могут его дополнить, переопределить или выключить через null. Имя MCP не может иметь два платформенных определения.

Режим документа `copy` создаёт управляемый файл, `link` — ссылку на read-only источник. Скиллы собираются с проектными файлами из `.agents/skills/`. Отключение capability снимает её управляемые документы, скиллы и MCP; установленная общая тулза и индекс остаются на диске.

## Добавить поставку

1. Для простого правила положите материал в общую папку и объявите capability в catalog.json.
2. Для связанного набора создайте `bundles/<name>/bundle.json`, поместите экспортируемые файлы рядом и зарегистрируйте bundle в каталоге.
3. Для новой тулзы добавьте обработчик установки и поведения в Go; JSON не является произвольным install script.
4. Проверьте доставку через `adc sync <id>` и гейты из [AGENTS.md](../AGENTS.md).

ADC проверяет источники всех деклараций, включая невыбранные: наличие, тип, границы путей, версии схем, поля exports, имена MCP и конфликты. Два выбранных бандла не могут поставлять разные скиллы с одним именем или разные версии одной тулзы. Правила conflicts и разные источники одного target документа также проверяются до доставки.

Источники общих импортированных скиллов указаны в [README библиотеки](skills/README.md), происхождение скилла бандла — в его README.

## Требования и вопросы активации

Необязательное поле `activation` в бандле описывает один экспортируемый MCP: `server`, список `requirements` и список `prompts`. Вопрос `key: "url"` задаёт адрес, его `default` — предложение для пользователя. Секретный вопрос содержит имя env-переменной в `key`, текст `label` и `secret: true`; значения ключей и секретные defaults в manifest не хранятся. Каталог проверяет экспорт сервера, допустимые ключи, уникальность вопросов и отсутствие секретного default.

При явном `adc project capability add` runtime запрашивает отсутствующие параметры из этого описания, сохраняет их локально и проверяет MCP. `adc mcp doctor --fix` использует те же вопросы для исправления настроек. Общая подготовка и синхронизация остаются неинтерактивными. Пример — [активация Obsidian](bundles/obsidian/bundle.json).
