[USAGE.md](../../../../delivery/skills/foxford-frontend-review/USAGE.md) содержит самостоятельный вызов, контракт передачи области и будущую точку после code-review до коммита implement. В поздней сверке первого цикла обнаружено изменение stat cache индекса: воспроизведение показало, что обычный git diff обновляет его даже при GIT_OPTIONAL_LOCKS=0. Статус смешанного вызова: **неполная проверка — требуется решение**. На /checkout default синтетический @team/ui v2 Button имеет радиус 8px, целевое значение fixture — 6px. Предложение: использовать штатный Button 8px либо отдельно расширить публичный API kit. Требуется явное решение разработчика; код спорной части сохранён, отклонение не принято, экран не объявлен завершённым. Этот запрос относится к тестовому сценарию и не является запросом пользователю изменить реальный продукт.

## Остальные режимы

[scenarios.json](scenarios.json) сохраняет реальные изолированные Git-fixtures, базу/HEAD, изменения, исходные/конечные хеши и фактический вывод основного агента для каждого read-only сценария:

- backend-only: «неприменимо», серверный .ts с CSS-строкой не изменён;
- insufficient: «неполная проверка», отсутствующие base/область и назначение unknown.ts требуют сведений, база HEAD~1 не придумана;
- project-priority: AGENTS.md разрешает точность card.css, new.css остаётся нарушением; legacy не подменяет документ;
- accepted-design: предыдущее явное решение учтено только для /checkout default, wrapper/public size допустимы;
- unknown-design: internal selector найден, измерения не выдуманы, зависимая часть требует решения.

Read-only означает анализ и отчёт: исправления и изменяющие проверки не запускались. Поэтому «проверено» в отдельных таких результатах означает завершённый анализ с явно перечисленными замечаниями, а не отсутствие нарушений или прохождение runtime-проверок. Индекс и все рабочие файлы этих сценариев сохранены.
