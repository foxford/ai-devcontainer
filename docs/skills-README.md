# `.agents/skills/` — проектный слой скиллов

Тех-скиллы (Claude / OpenCode / Codex / Hermes) приезжают из платформы и
обновляются централизованно — `adc update` на хосте. Здесь, в
репозитории проекта, лежит **только то, чем он отличается**: форки отдельных
файлов и собственные скиллы. Пустой каталог — нормальное состояние.

Что доступно прямо сейчас — в `AGENTS.skills.md` в корне репо (генерируется
при сборке, в `.gitignore`).

## Команды

```bash
adc skill list                     # что откуда приезжает
adc skill fork <скилл> [файл…]     # взять под правку (по умолчанию SKILL.md)
adc skill status                   # разошлась ли платформа под форками
adc skill unfork <скилл> [файл]    # вернуться на платформенную версию
adc skill sync                     # пересобрать после adc update
```

Если команды нет в PATH (контейнер поднят до её появления):
`ln -sfn /opt/ai-devcontainer/bin/adc ~/.local/bin/adc`.

## Как форкать

Перекрыть можно **любой** файл скилла, не только `SKILL.md`:

```bash
adc skill fork impeccable scripts/live.mjs
```

заберёт под проект один скрипт, а остальные файлы скилла продолжат ехать с
платформы. Форк фиксирует базовую версию в `.agents/skills-base/` — по ней
`status` показывает, что апстрим с тех пор изменился и диф стоит перечитать.

**Копировать платформенные скиллы сюда руками не нужно**: копия перекроет слой
платформы целиком, и проект перестанет получать по этому скиллу обновления —
ровно то, от чего уходили. Для этого и есть `fork`.

## Свой скилл проекта

Скилл, которого в платформе нет вовсе (специфика этого репозитория: свои
генераторы, домен, интеграции), заводится **прямо здесь** — каталогом с
`SKILL.md` внутри:

```
.agents/skills/
└── billing-invoices/          ← имя каталога = имя скилла, kebab-case
    ├── SKILL.md               ← обязателен: фронтматтер name + description
    ├── references/            ← необязательно: доки, которые читает агент
    └── scripts/               ← необязательно: код скилла
```

```markdown
---
name: billing-invoices
description: Расчёт и выставление счетов — схема таблиц, правила пропорций,
  типовые запросы. Звать при работе с биллингом и инвойсами.
---
```

`description` — единственное, по чему агент решает, брать скилл в работу:
пиши в нём КОГДА звать, а не только про что скилл.

Дальше `adc skill sync` (или новый контейнер) вмешает его в `.claude/skills/`
рядом с платформенными, и его увидят все четыре агента. Такой скилл — часть
кода проекта: коммить его в гит. Платформе он неизвестен и никуда не уезжает.

Имя обязано быть kebab-case (`^[a-z0-9]+(-[a-z0-9]+)*$`) — Hermes и DSH молча
пропускают каталоги, которые под шаблон не подходят.

Если скилл полезен не только этому проекту — его место в репозитории платформы,
в `skills/`: оттуда он раздастся во все проекты разом.

## Ссылка на файл скилла из хука или скрипта

Путь всегда `.claude/skills/<скилл>/…` — это собранное дерево, в нём лежат оба
слоя. `.agents/skills/` неполон по определению: там только отличия проекта, и
ссылка туда промахнётся мимо любого нефоркнутого файла. Промах при этом **тихий**:
хуки пишут `[ -f … ] || …`, чтобы не падать в проектах без скилла, — и от неверного
пути просто ничего не происходит, без единого сообщения. Образец — `.codex/hooks.json`.

## Про этот файл

Описание внутренностей (слои, собранное дерево `.claude/skills/`, кто из агентов
что читает) намеренно живёт не здесь, а в генерируемом `AGENTS.skills.md`: оно
зависит от версии платформы и в трекаемом файле проекта протухло бы. Здесь —
только команды, они стабильны. Обновляется этот README из платформы командой
`adc skill migrate`.
