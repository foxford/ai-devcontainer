# Проектные скиллы в `.agents/skills/`

Платформенные скиллы обновляются централизованно. В `.agents/skills/` проекта хранятся форки отдельных файлов и собственные скиллы. Каталог может быть пустым.

Список доступных скиллов находится в `AGENTS.skills.md` в корне репозитория. ADC создаёт его при синхронизации; файл входит в `.gitignore`.

## Команды

```bash
adc skill list                     # что откуда приезжает
adc skill fork <скилл> [файл…]     # взять под правку (по умолчанию SKILL.md)
adc skill status                   # разошлась ли платформа под форками
adc skill unfork <скилл> [файл]    # вернуться на платформенную версию
adc skill sync                     # пересобрать после adc update
```

На хосте команду устанавливает `adc install`. Внутри среды бинарник доступен по пути `/usr/local/bin/adc`.

## Как форкать

Чтобы изменить один файл скилла, укажите его при создании форка:

```bash
adc skill fork impeccable scripts/live.mjs
```

Команда скопирует указанный скрипт в проектный слой. Остальные файлы продолжат обновляться из платформы. Базовая версия форка сохраняется в `.ai-devcontainer/skills-base/`; команда `status` показывает изменения платформы относительно этой версии.

Используйте `fork` для нужных файлов. Копия всего скилла перекроет платформенный слой целиком и прекратит его обновления в проекте.

## Свой скилл проекта

Для собственного скилла проекта создайте каталог с `SKILL.md` внутри. Это подходит для знаний о домене, интеграциях и генераторах репозитория:

```
.agents/skills/
└── billing-invoices/          ← имя каталога = имя скилла, kebab-case
    ├── SKILL.md               ← обязателен: фронтматтер name + description
    ├── references/            ← необязательно: доки, которые читает агент
    └── scripts/               ← необязательно: код скилла
```

```markdown
---
name: billing-invoices
description: Расчёт и выставление счетов — схема таблиц, правила пропорций,
  типовые запросы. Звать при работе с биллингом и инвойсами.
---
```

В `description` укажите, в каких задачах нужен скилл. По этому полю агент решает, применять ли его.

Команда `adc skill sync` или подготовка новой среды добавит его в `.claude/skills/` рядом с платформенными. Проектный скилл хранится в Git этого проекта и доступен его агентам.

Имя должно соответствовать kebab-case (`^[a-z0-9]+(-[a-z0-9]+)*$`). Hermes и DSH пропускают каталоги с неподходящими именами.

Общий скилл разместите в `delivery/skills/` платформы: оттуда он доставляется во все проекты.

## Ссылка на файл скилла из хука или скрипта

Используйте путь `.claude/skills/<скилл>/…`: это собранное дерево с обоими слоями. Каталог `.agents/skills/` содержит только проектные отличия. Ссылка на нефоркнутый файл в нём не сработает, а хук с проверкой `[ -f … ]` может пропустить вызов без сообщения.

## Про этот файл

Устройство слоёв и доступ агентов описаны в генерируемом `AGENTS.skills.md`, который соответствует текущей платформе. Этот README обновляется командой `adc skill migrate`.
