# Установка ADC

Команды установки для macOS/Linux и Windows находятся в [README](../README.md#начать-работу). Скрипт сам клонирует платформу в пользовательский каталог или обновляет существующую установку.

## Поддерживаемые системы

ADC и Orca устанавливаются на Linux и macOS (amd64/arm64) и Windows (amd64). CLI также собирается для Windows arm64, но закреплённый релиз Orca содержит только пакет Windows x64.

Полная проверка установки и среды выполнена на Linux amd64. В CI настроены нативные проверки Go для Linux, macOS и Windows. Установка Docker Desktop и подключение хостовой Orca на macOS/Windows требуют проверки на этих ОС.

## Что делает установщик

Скрипт проверяет Git и средства загрузки, устанавливает недостающие компоненты, скачивает закреплённую версию Go с проверкой SHA-256 и собирает ADC. Go хранится в каталоге платформы; устанавливать его в систему заранее не нужно. На Windows не требуется Bash, на хосте не нужны jq и rsync.

Далее `adc install` устанавливает бинарник, подключает PATH и автодополнение, проверяет Docker, устанавливает хостовую Orca и создаёт конфигурацию рабочей среды. Недостающий Docker устанавливается через apt/dnf/pacman на Linux, Homebrew Docker Desktop на macOS или winget Docker Desktop на Windows.

Установка системных компонентов может потребовать пароль администратора, UAC, повторный вход или перезагрузку. Установщик сообщает, что нужно сделать перед запуском среды, и продолжает установку остальных компонентов.

## Orca

Версия, ссылки на пакеты и SHA-256 закреплены в [runtime/orca-lock.json](../runtime/orca-lock.json). На Linux устанавливаются распакованный AppImage и пункт меню, на macOS приложение помещается в `~/Applications`, на Windows запускается официальный установщик.

На Linux установщик проверяет библиотеки Electron через `ldd` и устанавливает недостающие пакеты. Приложению Orca нужна графическая сессия. Сервер Orca работает внутри контейнера; его зависимости входят в образ.

Флаг `adc install --no-orca` пропускает установку хостового клиента Orca.

## PATH и автодополнение

ADC добавляет свой бинарник в пользовательский PATH и подключает автодополнение для Bash, Zsh, Fish и PowerShell. Установщик меняет только свои блоки в профилях оболочек; повторный запуск не создаёт дубликатов. После установки откройте новый терминал.

Скрипт автодополнения можно получить отдельно:

```sh
adc completion bash
adc completion zsh
adc completion fish
adc completion powershell
```

Внутри среды установка и восстановление инструментов выполняются командой `adc tools install`. Graphify устанавливается для проектов с выбранной capability; OmniRoute поставляется вместе со штатными инструментами. Один инструмент можно восстановить отдельно: `adc tools install graphify` или `adc tools install omniroute`.

## Обновление и диагностика

Повторный запуск команды установки обновляет клон платформы, пересобирает ADC и повторяет настройку. Команда `adc update` обновляет клон и собирает образ; для применения образа выполните `adc workspace start`.

Если среда не запускается, начните с `adc doctor`, `adc workspace status` и `adc workspace logs`.

## Разработка установщика

Точка входа CLI находится в `bin/adc/`, хостовая логика в `bin/adc/host/`, доставка внутри контейнера в `bin/adc/runtime/`, общие операции в `bin/adc/internal/`. POSIX- и PowerShell-скрипты подготавливают машину к запуску бинарника.

Чтобы собрать CLI из локального клона:

```sh
go build -o .build/adc ./bin/adc
.build/adc --help
```

`.build/adc` — локальный бинарник для разработки. Установленная команда `adc` запускается напрямую. Проверки описаны в [AGENTS.md](../AGENTS.md#обязательные-гейты).
