# AGENTS.md — ai-devcontainer

Ты работаешь в репозитории **платформы**, а не проекта. Отсюда раздаются
окружение и шаблон для всех проектов foxford — цена ошибки выше обычной.

## Структура (кратко)

| Путь | Что это |
|---|---|
| `Dockerfile` | образ dev-base (тулчейн); в него печётся ТОЛЬКО `tooling/setup.sh` |
| `tooling/` | скрипты post-create/install-ai-tools/wire-skills — монтируются в проекты read-only |
| `skills/` | **стоковые тех-скиллы платформы** — раздаются во все проекты overlay'ем, в проект НЕ копируются |
| `mcp/` | **стоковые MCP-серверы платформы** (`servers.json`) — раздаются тем же overlay'ем на Claude + Codex + Hermes + DSH |
| `docs/` | **платформенные доки проекта**: `AGENTS.platform.md` (контракт для агентов), `MONOREPO.md`, README слоя скиллов, README каталога планов, образец секретов MCP — раздаются симлинками. Раздаётся не всё: список в `tooling/wire-docs.sh`, остальное (`devcontainer-delivery.md`) — про устройство самой платформы |
| `skeleton/<type>/` | **реестр скаффолдов** — источник правды о проекте каждого типа: `.scaffold.json` (label + подстановка имени) плюс сам шаблон. Сейчас один тип, `pnpm-monorepo/`: монорепа (Nx+pnpm), пакеты `@foxford/*`, `.hermes`; `.agents/skills` в нём пустой — под проектные форки |
| `bin/ai-devcontainer` | CLI: new / ensure-image / update / doctor / skill / mcp / plans |
| `install.sh` | бутстрап машины разработчика (`curl \| bash`) |
| `tests/` | bats-тесты на `tooling/*.sh` + `bin/ai-devcontainer`; `tests/bats/lib/` — сами фреймворки (bats-core/-support/-assert, git submodules), не трогать руками |

## Quality gates (обязательны перед завершением задачи)

```bash
cd skeleton/pnpm-monorepo && pnpm run lint && pnpm run type-check && pnpm run test && pnpm run build
```

Менял `skeleton/pnpm-monorepo/e2e/` или `playwright.config.ts` → дополнительно:
```bash
cd skeleton/pnpm-monorepo && pnpm run e2e:type-check && pnpm run e2e
```

Менял `Dockerfile`/`tooling/setup.sh` → дополнительно:
```bash
AI_DEVCONTAINER_HOME="$PWD" bash bin/ai-devcontainer ensure-image   # образ собирается
ai-devcontainer new smoke /tmp/smoke && rm -rf /tmp/smoke        # скелет генерится
```

Менял что-то в `tooling/*.sh` или `bin/ai-devcontainer` → обязательно:
```bash
bash tests/run.sh   # весь bats-набор; для одного файла — bash tests/run.sh tests/<каталог>/
```
Новый код в этих скриптах без соответствующих тестов не считается завершённым.

## Жёсткие правила

- `skeleton/` — единственный источник правды о содержимом проекта. Ничего
  проектного вне skeleton не заводить. Исключение по замыслу — `skills/` и
  `mcp/`: они принадлежат платформе, а не проекту, и в проект не копируются.
- Стоковый скилл правится в `skills/` — это меняет его во всех проектах разом.
  Проектная правка живёт в самом проекте (`ai-devcontainer skill fork`), сюда не тащится.
- Общее правило для агентов — в `docs/AGENTS.platform.md`, а не в `skeleton/AGENTS.md`:
  первый раздаётся всем проектам, второй остаётся у проекта под его специфику.
- Не добавлять зависимости без явного разрешения пользователя.
- Рабочие артефакты (node_modules, .nx, build, pnpm-store) не коммитить.
- `--passWithNoTests` — только у таргета `test`, не в комбинированных `run-many`.

## Скиллы

Два слоя, приоритет у проектного (`tooling/wire-agent-skills.sh`):

| Слой | Где | Что там |
|---|---|---|
| платформенный | `skills/` (в проекте — `/opt/ai-devcontainer/skills`, read-only) | стоковые скиллы, общие для всех проектов |
| проектный | `<repo>/.agents/skills/` | только отличия: форки файлов и свои скиллы |

Собранное дерево — `<repo>/.claude/skills/` (в .gitignore, пересобирается).
Читают его четыре агента: Claude и OpenCode напрямую, Codex — симлинками в
`~/.codex/skills/`, DSH — симлинками в `<repo>/.dsh/skills/` (его роут ранга
100; `.agents/skills` он читает и сам, но там по замыслу одни форки).
Проза симлинкуется на слой (правка в платформе видна сразу), код копируется —
иначе Node резолвил бы `import` от реального пути и молча игнорировал форк.

Перекрыть можно любой файл, не только `SKILL.md`. Работа с форками — одной
командой и на хосте, и в контейнере: `ai-devcontainer skill <list|status|fork
&lt;skill&gt; [файл…]|unfork|migrate|sync>`. Реализация — `tooling/skill.sh`.
Базовая версия форкнутого файла лежит в `<repo>/.agents/skills-base/` — по ней
`status` показывает, что платформа уехала.

Полный список скиллов с описаниями — в [AGENTS.skills.md](AGENTS.skills.md) (генерируется, в .gitignore). Прочитай его, если подбираешь скилл под задачу.

### Импортированные скиллы и рамка платформы

Часть скиллов приехала из чужих репозиториев — провенанс в `skills-lock.json`
(ведётся руками; ни один скрипт его не читает и не пишет). Они написаны про
«свой проект с нуля» и, если позвать их без рамки, считают себя вправе поставить
зависимость, сменить стек и переписать чужой стайлгайд.

Поэтому в тело таких скиллов вставляется **рамка платформы** — блок в маркерах
`<!-- ai-devcontainer:override:start … end -->` сразу после фронтматтера, плюс
переписанный `description` (он решает, перехватит скилл задачу или нет).
Расхождение помечено полем `localOverride` в `skills-lock.json`.

- **Переимпорт из `source` затрёт рамку.** После него — вернуть блок по маркерам.
- Рамка держит: применимость по мандату, запрет на установку зависимостей,
  `pnpm` вместо `npm`, стек из проекта, побочные записи файлов — с предупреждением.
- Правишь такой скилл — правь рамку, а не тело апстрима: диф остаётся мержабельным.

Фронтенд-скиллы (`senior-frontend` как точка входа, `impeccable`,
`design-taste-frontend`, `redesign-existing-projects`, `stitch-design-taste`)
связаны в один маршрут: правило и мандаты — в `docs/AGENTS.platform.md`, секция
«Фронтенд», разводка по задачам — в `skills/senior-frontend/references/composition_map.md`.

## MCP-серверы

Те же два слоя и тот же приоритет (`tooling/wire-mcp.sh`):

| Слой | Где | Что там |
|---|---|---|
| платформенный | `mcp/servers.json` | стоковые серверы, общие для всех проектов |
| проектный | `<repo>/.agents/mcp.json` | только отличия; `null` вместо объекта — выключить платформенный |

Слияние **рекурсивное и посерверное**: проект может переопределить у
платформенного сервера один `env`, оставив `command`/`args` платформенными.
Плейсхолдер `${REPO_ROOT}` раскрывается в абсолютный корень проекта.

Раздаётся в четыре места, потому что проектного скоупа для MCP есть только у
одного из четырёх агентов:

| Агент | Куда пишем |
|---|---|
| Claude Code | `<repo>/.mcp.json` (генерируется, в .gitignore) |
| Codex | `~/.codex/config.toml` через `codex mcp add` |
| Hermes | `~/.hermes/config.yaml`, ключ `mcp_servers`, напрямую |
| DSH | `~/.dsh/cordis.patch.yml`, patch-op `insert`, в маркерах |

Home-скоуп у Codex, Hermes и DSH не мешает: в devcontainer'е `~/.codex`,
`~/.hermes` и `~/.dsh` — пер-проектные bind-маунты. Hermes пишем напрямую, а не
через `hermes mcp add`: тот интерактивен и коннектится к серверу на этапе
добавления — в postCreate без TTY это висяк. OpenCode не раздаём: у него свой
формат.

У DSH формат не словарь серверов, а **список патчей композиции Cordis**: каждый
сервер — отдельный инстанс плагина `@deepseek-ai/dsh-mcp-client`, наш
`command/args/env` ложится на `transport: stdio`, а `url/headers` — на
`transport: streamable-http` (заголовки он, в отличие от Codex, умеет штатно).
Файл общий с человеком, поэтому свой блок держим в маркерах
`# ai-devcontainer:mcp:start … end` и перезаписываем только его. OAuth-серверы
туда не едут по той же причине, что в Codex.

Две грабли оплачены заранее. Пустой патч-лист dsh пишет как `[]`, и дописать
элементы списка после него нельзя — это не «список из одного», а сломанный
документ, с которым агент не поднимется вовсе; плейсхолдер снимаем. И перед
записью результат прогоняется через парсер YAML (если в окружении есть
pyyaml): сломать человеку конфиг агента хуже, чем не раздать ему MCP — при
непроходе файл остаётся как был, а в лог идёт причина.

**Версии пиним намертво.** Сервер стартует у агента в начале сессии: `@latest`
означал бы поход в сеть и смену поведения посреди работы. Пин `@playwright/mcp`
— единственный в репозитории: браузер под него ставит post-create, вычитывая
пин оттуда же (`npx -y --package=@playwright/mcp@<пин> playwright install chromium`).

### Секреты

Значения берутся из `<repo>/.agents/mcp.secrets.env` (в .gitignore, права 600),
поверх — окружение процесса. Сам файл заводит wire-mcp: копировать образец
руками не надо, а копия, сохранившая симлинк (`cp -a`, копипаст в проводнике
VS Code), дала бы ссылку в read-only слой платформы — редактор отказывался бы
её сохранять с EROFS. Такую ссылку на месте секретов wire-mcp заменяет файлом. Образец с именами переменных — `docs/mcp-secrets.env.example`,
раздаётся симлинком в `.agents/mcp.secrets.env.example` (не копией: список
переменных растёт вместе с набором стоковых серверов, копия в проекте молча
отстала бы). `${ИМЯ}` раскрывается wire-mcp'ом в любом строковом значении.

Раскрываем **мы**, а не агент: `${VAR}` умеют Claude и Hermes, на Codex не
проверено, а схема «у двоих работает, у третьего молча пусто» хуже честной.
Цена — токен плейнтекстом в `.mcp.json` и `~/.codex/config.toml`; это не новый
класс риска, там же лежат логины самих агентов, и ничего из этого не в гите.

### x-requires — гейт раздачи

Слой платформы общий, поэтому сервер, которому не хватает условий, не
раздаётся вовсе, а не падает у агента на первом вызове:

```json
"x-requires": ["path:/home/node/.cache/ms-playwright/chrome-current"]
```

Пропуск логируется. Именно так `chrome-devtools` не появляется пока не установлен браузер.

Рядом есть вторая метка, `x-oauth: true`. Она не про раздачу, а про Codex:
OAuth-сервер туда автоматически не добавляется, wire-mcp только печатает
команду.

### Стоковые серверы

| Сервер | Что делает | Условие раздачи |
|---|---|---|
| `playwright` | браузер агента: клики, снапшоты, консоль | всегда |
| `chrome-devtools` | профилирование, трейсы, троттлинг, Core Web Vitals | симлинк `chrome-current` (ставит post-create) |
| `figma` | фреймы, токены дизайна, код по выделению | `FIGMA_MCP_ENABLED` (по умолчанию выключен) |

Токен идёт **заголовком** `Authorization`, хотя сервер принимает и
`?access_token=` в query. Query-строка уезжает в скриншот `.mcp.json` — заголовок не уезжает никуда. Плейнтекстом в конфиге
агента токен лежит всё равно, подстановки раскрывает wire-mcp.

Цена — Codex: заголовки он умеет только ключом `http_headers` в `config.toml`,
а `codex mcp add` их не выставляет. В Codex его вписывают руками,
готовый блок печатает `ai-devcontainer mcp sync`. Запись от прошлой раздачи (без
заголовков — она бы не заработала) wire-mcp при этом снимает сам, а вписанную
руками отличает по наличию `http_headers` и не трогает.

**OAuth-серверы (`figma`) требуют двойной осторожности, оплаченной граблями.**
Во-первых, попав в конфиг, такой сервер просит авторизацию при КАЖДОМ старте
агента во всех проектах разом — поэтому он за явным опт-ином. Во-вторых, логин
в Codex всё равно ручной, а исторически `codex mcp add --url` ещё и коннектился
к серверу прямо при добавлении, поднимая интерактивный OAuth-промпт: в
postCreate это висяк. Поэтому серверы с `x-oauth` в Codex **не добавляются
автоматически**, wire-mcp только печатает команду.

## DSH (DeepSeek Harness)

Четвёртый агент платформы: агентный рантайм DeepSeek, MIT, релиз 13.08.2026.
Ставится как codex — npm global в `/opt/ai-tools` (`@deepseek-ai/dsh`), Node в
образе 26.x при требуемых `^22.19 || >=24`. **Установка не блокирующая**: dsh в
developer preview и апстрим обещает ломающие изменения, а сборка контейнера не
должна падать из-за агента, которым проект может и не пользоваться.

Точки входа: `dsh web` (Web UI на 127.0.0.1:3080), `dsh --profile headless "…"`
для одного прогона, ACP и JSON-RPC поверх stdio для SDK-клиентов. Ключ —
`DEEPSEEK_API_KEY`: окружение → `~/.dsh/.credentials.yaml` → `.env` →
`~/.dsh/.env`. Разобрать состав композиции — `dsh web --dump-config`.

Что он берёт бесплатно, а что пришлось раздавать:

| Что | Как у dsh | Что делаем мы |
|---|---|---|
| Инструкции | сам читает `AGENTS.md` и `CLAUDE.md` (+`*.local.md`) от корня репо вниз, плюс `$DSH_HOME/AGENTS.md` | ничего |
| Скиллы | шесть роутов по рангам; проектные — `.dsh/skills` (100) и `.agents/skills` (200) | симлинки собранного дерева в `.dsh/skills` — иначе он увидел бы одни форки |
| MCP | проектного скоупа НЕТ, только патч композиции в `$DSH_HOME` | генерируем блок в `~/.dsh/cordis.patch.yml` |
| Профили, сессии | всё в `$DSH_HOME` | пер-проектный bind-маунт `~/.dsh`, как у `~/.codex` |

Имя скилла у него обязано быть kebab-case (`^[a-z0-9]+(-[a-z0-9]+)*$`), иначе
каталог молча пропускается; `serverName` у MCP — `[A-Za-z0-9_-]{1,32}`.
`wire-agent-skills.sh` и `wire-mcp.sh` проверяют оба шаблона и предупреждают,
а не молчат. Рекурсивный обход `**/SKILL.md` у него не поддержан — скиллы
ищутся ровно на первом уровне роута.

**Апстрим в preview — при обновлении сверять форматы.** Ломается в первую
очередь раздача MCP (схема `dsh-mcp-client` и структура patch-op), потом ранги
роутов скиллов. Проверка на месте: `dsh web --dump-config` и присутствие
серверов в сессии.
