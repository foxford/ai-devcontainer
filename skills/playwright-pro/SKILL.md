# Skill: Playwright — e2e-тесты и браузер для агента

## Когда использовать

- Пишешь, чинишь или мигрируешь end-to-end тесты.
- Тест «падает через раз» — надо разобрать flaky.
- Нужно **посмотреть** на живое приложение: воспроизвести баг, проверить, что
  правка легла, снять скриншот, прочитать ошибку в консоли браузера.

## Два инструмента, не путать

| | Раннер (`@playwright/test`) | Браузерный MCP (сервер `playwright`) |
|---|---|---|
| Что это | тесты, которые гоняет CI | браузер, которым агент рулит вживую |
| Как звать | `pnpm run e2e` из корня | инструменты `browser_*` в списке твоих tools |
| Когда | закрепить поведение навсегда | разведать поведение здесь и сейчас |
| Живёт | `e2e/` + `playwright.config.ts` | `mcp/servers.json` платформы |

Нормальный порядок работы: **разведал через MCP → закрепил тестом в `e2e/`**.
Разведка без теста ничего не гарантирует, а тест, написанный вслепую по
предположениям о вёрстке, обычно врёт локаторами.

## Раннер

Тесты лежат в **корневом `e2e/`**. Это не пакет монорепы: `project.json` у него
нет, в nx-граф и pnpm-воркспейс он не входит, `nx run-many` его не подхватит.

```bash
pnpm run e2e                  # прогон
pnpm run e2e -- --grep "логин"   # по имени
pnpm run e2e -- --last-failed    # только упавшие в прошлый раз
pnpm run e2e:type-check       # tsc по спекам — playwright типы НЕ проверяет
pnpm run e2e:report           # html-отчёт последнего прогона
pnpm run e2e:install          # доставить браузер
```

Браузеры лежат в volume (`$PLAYWRIGHT_BROWSERS_PATH`), а не в образе: их ревизия
привязана к версии пакета, а образ один на все проекты. Ставит их post-create.

**e2e не входит в quality gates.** `pnpm test` — это vitest; e2e требует
поднятого приложения и в общий прогон не лезет. Гоняй его отдельно и явно.

Приложение под тестами: `webServer` в `playwright.config.ts` (раннер сам поднимет
и погасит) либо `E2E_BASE_URL=http://…` перед командой.

## Браузерный MCP

Инструменты `browser_navigate`, `browser_snapshot`, `browser_click`,
`browser_type`, `browser_fill_form`, `browser_take_screenshot`,
`browser_console_messages`, `browser_network_requests`, `browser_evaluate` и
ещё десяток. Появляются у Claude, Codex, Hermes и DSH одинаково — раздаёт
`tooling/wire-mcp.sh` платформы.

Как пользоваться:

- **`browser_snapshot` вместо скриншота — по умолчанию.** Это дерево
  доступности текстом: дёшево по токенам, и из него сразу видны роли и имена,
  то есть готовые `getByRole`-локаторы для будущего теста. Скриншот бери,
  когда вопрос именно про внешний вид.
- Профиль **изолированный, в памяти**: между сессиями логин не переживает.
  Нужен залогиненный сценарий — проходи логин шагами или используй
  `storageState` (см. `reference/fixtures.md`).
- Выхлоп (снапшоты, скриншоты, трейсы) падает в `.playwright-mcp/` в корне
  репо; в гите его нет. Пути в ответах инструментов — оттуда.
- **`file://` заблокирован**, доступ ограничен рабочим каталогом. Локальный
  html открывай через http (подними сервер), а не файлом. Если проекту это
  действительно мешает — снимается флагом `--allow-unrestricted-file-access`
  в проектном слое `.agents/mcp.json`, не правкой платформы.
- Браузер **headless и без песочницы** — дисплея и user namespaces в контейнере
  нет. `--headed` не заработает.

## Золотые правила

1. `getByRole()` вместо CSS/XPath — переживает рефакторинг вёрстки.
2. Никогда `page.waitForTimeout()` — только веб-первые ассерты.
3. `expect(locator)` ретраится сам; `expect(await locator.textContent())` — нет.
4. Каждый тест изолирован: ни общего состояния, ни зависимости от порядка.
5. `baseURL` в конфиге — никаких URL, зашитых в спеку.
6. Ретраи: в CI, локально `0`. Падение надо видеть сразу.
7. Трейсы `'on-first-retry'` — отладка есть, прогон не распухает.
8. Фикстуры вместо глобалов — `test.extend()` для общего состояния.
9. Один сценарий на тест; несколько связанных ассертов внутри — нормально.
10. Мокать только чужие сервисы. Своё приложение не мокаем — иначе тест
    проверяет мок, а не продукт.

## Приоритет локаторов

```
1. getByRole()        — кнопки, ссылки, заголовки, поля форм
2. getByLabel()       — поля с подписью
3. getByText()        — неинтерактивный текст
4. getByPlaceholder() — инпуты с плейсхолдером
5. getByTestId()      — когда семантического варианта нет
6. page.locator()     — CSS/XPath, последнее средство
```

`testIdAttribute` в конфиге раннера совпадает с дефолтом MCP (`data-testid`):
`getByTestId` в тесте и снапшот агента указывают на один и тот же элемент.

выполнить. Всё, что они делали, делается руками по этому файлу и `reference/`.
