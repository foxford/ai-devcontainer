# Контракт общей среды ADC

В начале задачи прочитай карту проектов `/workspace/AGENTS.workspace.md`, затем `AGENTS.md`, `README.md` и `SPEC.md` затронутых репозиториев, если эти файлы есть. Вложенные инструкции действуют внутри своих каталогов. Меняй соседний проект только тогда, когда он входит в задачу пользователя и доступен на запись.

Карта и общие знания помогают учитывать связи проектов. Выбирай источники по задаче; не загружай заранее всё содержимое среды. У источников указаны происхождение и дата регистрации. Проверяй текущий файл, прежде чем полагаться на сведения.

Используй стек, пакетный менеджер, проверки и порядок релизов конкретного репозитория. Возможности проекта перечислены ниже и в `.agents/project.json`. Не устанавливай зависимости без разрешения пользователя. Не коммить и не пушь без явного поручения. Рабочие артефакты не добавляй в Git.

Перед завершением выполни проверки проекта и сообщи результат. Обновляй архитектурную документацию вместе с кодом. Многошаговую задачу фиксируй в `plans/`, если проект использует эту конвенцию.

Платформенные скиллы доступны всем проектам. Проектные варианты описаны в `AGENTS.skills.md`: выбирай вариант затронутого checkout. Имена проектных MCP содержат префикс проекта и checkout; используй сервер только для его области. Локальные секреты не помещай в Git.

При создании и содержательном обновлении README используй `readme-writer`, если он доступен в каталоге скиллов агента или `AGENTS.skills.md`. Сначала прочитай его `SKILL.md`; для затронутого checkout выбирай проектный вариант, если он есть. Соблюдай язык и правила документации проекта; при отсутствии скилла продолжай по ним.

При редактуре русского текста и финальной вычитке собственного русского черновика используй доступный `humanizer`, предварительно прочитав его `SKILL.md`; проектный вариант затронутого checkout имеет приоритет. Это относится и к тексту README, документации, описаний PR и релиз-ноутов в текущей задаче. Для русского README сначала применяй `readme-writer`, затем `humanizer`, если доступны оба. Сохраняй факты, смысл, жанр и технический тон; код, команды, цитаты и иноязычный текст не переписывай по русским маркерам. При отсутствии скилла вычитывай текст по правилам проекта.

Orca управляет рабочими областями, worktree, терминалами и задачами. Справку читай через `orca --help`, `orca skills get orca-cli` и `orca skills get orchestration --full`. Координатор явно запускает исполнителей и проверяет результаты; создание task или run само по себе не запускает планировщик. Для задачи нескольких проектов укажи checkout и ветку каждого, а также общий критерий готовности. Запись во внешний трекер требует поручения пользователя.

Перед запуском агента в новом worktree выполни `adc sync <path>`. Остановка или пересоздание контейнера завершает живые процессы. Код, worktree, конфигурации и сохранённая история остаются в маунтах и томах Docker. Возобновление сессии зависит от возможностей агента.
