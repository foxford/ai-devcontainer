# AGENTS.md — ai-devcontainer

Это платформа общей рабочей среды разработчика. Один `adc` подключает существующие репозитории к одному Docker runtime. Проектный devcontainer и scaffold больше не поставляются. Хосты: Linux, macOS, Windows.

## Структура

| Путь | Назначение |
|---|---|
| `bin/adc/` | Go CLI на Cobra; точка входа и дерево команд |
| `bin/adc/host/` | Установка, Docker lifecycle и регистрация проектов на хосте |
| `bin/adc/runtime/` | Доставка документов, skills и MCP, настройка агентов и Orca внутри контейнера |
| `bin/adc/internal/` | Общие типы, каталог доставки, файловые операции и блокировки |
| `install.sh`, `install.ps1` | Bootstrap: prerequisites, проверенный Go для сборки, запуск adc install |
| `runtime/Dockerfile` | Единственный образ: Linux тулчейн, оболочки, ADC и Orca |
| `runtime/` | Dockerfile, тонкий shell-env и версии устанавливаемых приложений |
| `runtime/orca-lock.json` | Единственный пин Orca: версии, URL и SHA-256 |
| `delivery/instructions/AGENTS.platform.md` | Общий контракт без привязки к pnpm или типу проекта |
| `delivery/catalog.json` | Базовая доставка, простые возможности и регистрации бандлов |
| `delivery/bundles/<name>/bundle.json` | Декларация exports бандла: инструкции, скиллы, документы, MCP и тулзы; источники рядом |
| `delivery/documents/` | Документы, доставляемые в проекты; документация самого ADC находится в docs/ |
| `delivery/skills/README.md` | Источники импортированных скиллов и локальные изменения |
| `delivery/instructions/capabilities/` | Выбираемые проектные правила: pnpm/Nx, Changesets, фронтенд, браузерные MCP |
| `delivery/skills/`, `delivery/mcp/` | Общие платформенные слои, не вендорятся в проекты |
| `bin/adc/integration/` | Go smoke-тест настоящего Docker runtime; остальные Go tests рядом с кодом |

## Обязательные гейты

```sh
gofmt -w bin/adc
go vet ./...
go test -race ./...
go build -o .build/adc ./bin/adc
```

Docker smoke с реальными Graphify и OmniRoute: `ADC_TOOL_BUNDLES_INTEGRATION=1 ADC_INTEGRATION=1 go test -v -count=1 -timeout=35m ./bin/adc/integration`.

После правок Go перед следующей значимой частью задачи проверяй сборку. В CI форматирование проверяется без изменения файлов; Go тестируется на Linux/macOS/Windows и компилируется на amd64/arm64. При правках runtime обязателен реальный Docker smoke двух репозиториев, Orca, worktree, оболочек и персиста. Scaffold и его Node-гейтов больше нет: он удалён по решению пользователя. Новый код движков без соответствующих тестов не завершён.

## Ограничения

- Не добавляй зависимости без явного разрешения пользователя. Cobra v1.10.2 и go.yaml.in/yaml/v3 v3.0.5 разрешены 2026-10-09. Их транзитивные зависимости фиксируются go.sum.
- Для изолированного сканера humanizer разрешены razdel 0.5.0 и pymorphy3 2.0.6 (2026-10-13); пины находятся в requirements.txt скилла.
- У скиллов и бандлов есть `meta.json`, у MCP — `<name>.meta.json` рядом с источником. У каждого доставляемого документа и инструкции есть `<полное-имя-файла>.meta.json` рядом с исходником, например `AGENTS.platform.md.meta.json`; их `kind` — `document`. При изменении единицы повышай её `version` по SemVer; для экспорта бандла повышай также версию бандла. Уведомления ADC сравнивают только эти версии.
- Не коммить и не пушь. Не коммить бинарники, кеши, node_modules, build или .nx.
- Хостовые операции реализуются на Go. Bootstrap POSIX/PowerShell только доводит машину до запуска бинарника. Внутренняя логика также на Go. Shell остаётся только в bootstrap, экспорте окружения, проектном motd и официальных установщиках внешних тулз.
- Граница host/runtime явная: ADC_RUNTIME=1. Не определяй её правами каталога.
- Не монтируй весь домашний каталог хоста или Docker socket. Регистрация проекта явно определяет доступ; read-only проект не изменяется доставкой.
- Проектный AGENTS.md сохраняется. Доставка изменяет только управляемые блоки и файлы с маркером ai-devcontainer:generated. Claude @-импорт получает настоящий файл AGENTS.platform.md, потому что импорт симлинков не работает.
- Общий skill меняется в delivery/skills/, skill бандла — внутри delivery/bundles/. Форк — в .agents/skills проекта. Служебное состояние — .adc/, человеческие конфиги — .agents/. Прежний .ai-devcontainer/ сохраняется при миграции до явного cleanup.
- Все пути источников в delivery/catalog.json отсчитываются от delivery/. В bundle.json источники exports отсчитываются от каталога бандла и не выходят из него. Target документа отсчитывается от подключённого проекта. Не добавляй неявные корни по типу файла; каталог проверяет существование всех источников и имён MCP до доставки.
- Общие home навыки не могут зависеть от последнего синхронизированного репозитория. Проектные варианты получают namespace checkout и область.
- MCP имеет четыре рекурсивных слоя: global, user, project, local; null выключает сервер. Проектное бьёт глобальное, моё бьёт общее. Секреты проекта не коммитятся. Общие агентные конфиги изменяются под одним lock.
- Обновляй SPEC.md по фактам вместе с кодом. Задачи — plans/<год>/<дата>-<slug>/. research.md дополняется, task.md отражает текущее состояние. Не объявляй непроверенное реализованным или beta-интеграцию стабильной.
- В Markdown каждый абзац записывай одной строкой: переносы для ширины окна делает редактор. README описывает назначение продукта, пользу и действия разработчика; детали реализации и установки выноси в справочные документы.
- Проверки платформы пишутся на Go. Старые Bats-наборы и submodules удалены по решению пользователя; не возвращай их.

## Импортированные скиллы

После переимпорта восстанавливай рамку; правь её, сохраняя upstream тело. Маршрут фронтенда — delivery/skills/senior-frontend/references/composition_map.md. Выбирай skill по задаче и мандату, учитывая стек затронутого репозитория.
