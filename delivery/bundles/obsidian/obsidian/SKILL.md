# Obsidian

Два независимых механизма. Первый работает всегда и без вопросов. Второй —
MCP-сервер, который может быть не подключён, и это нормально.

## Когда использовать

- Пользователь просит сохранить заметку, решение, сводку сессии, план или
  ресёрч **в Obsidian** («запиши в obsidian», «сохрани заметку», «занеси в
  vault»).
- Пользователь просит **найти, прочитать или обновить** что-то в его
  Obsidian-vault'е.
- Пользователь просит собрать код-граф проекта как vault — это `graphify
  --obsidian`, отдельный флаг соседнего скилла `/graphify`, не этот скилл
  сам по себе (см. «Отношение к graphify» ниже).

**Не использовать** как способ просто «записать markdown-файл» — если
пользователь не упомянул Obsidian/vault явно, обычный файл в репозитории
(или `plans/`, если это задача) уместнее: vault — это его личное
пространство, туда не стоит сваливать то, о чём не просили.

## Vault-каталог

ADC не создаёт отдельный vault и не монтирует личные заметки автоматически. Если пользователь подключил Git-репозиторий vault как проект ADC, найди его путь и разрешённый доступ в `/workspace/AGENTS.workspace.md`. Если vault не подключён, не угадывай путь и не создавай папку вместо него. Для сохранения заметки уточни или используй явно указанный пользователем vault. Read-only источник можно читать, но нельзя изменять.

Сохраняй Markdown, frontmatter, теги и `[[wikilinks]]` по правилам конкретного vault. Обычную документацию проекта оставляй в репозитории, если пользователь не попросил сохранить её в Obsidian.

## MCP Obsidian

Capability `obsidian` доставляет MCP для Obsidian на хосте через плагин Local REST API. Для настройки из терминала проекта выполни `adc project capability add obsidian`: CLI спросит адрес MCP и ключ `OBSIDIAN_API_KEY`, сохранит их локально и проверит подключение. Для диагностики и исправления используй `adc mcp doctor obsidian --fix`. Точные шаги подключения описаны в `docs/workspace.md` платформы. ADC не устанавливает Obsidian и его плагины автоматически.

Если инструментов Obsidian нет, сообщи об этом и используй файловый доступ только к явно подключённому vault. Наличие MCP не даёт разрешения изменять заметки без поручения пользователя.

Основные инструменты (точные названия могут отличаться версией плагина):

| Инструмент | Что делает |
|---|---|
| `vault_list` | список файлов/подкаталогов vault'а |
| `vault_read` | прочитать файл — контент, frontmatter, теги |
| `vault_write` | создать или перезаписать файл |
| `vault_append` | дописать в конец файла |
| `vault_patch` | точечно поправить заголовок/блок/поле frontmatter |
| `vault_delete` / `vault_move` / `vault_copy` | удалить / переименовать / скопировать |
| `vault_get_document_map` | заголовки, блок-ссылки, frontmatter файла |
| `search_simple` | полнотекстовый поиск (встроенный поиск Obsidian) |
| `search_query` | поиск по метаданным через JsonLogic |
| `tag_list` | все теги vault'а со счётчиками |
| `command_list` / `command_execute` | список / выполнение команд Obsidian |
| `active_file_get_path` | путь файла, открытого в Obsidian прямо сейчас |
| `open_file` | открыть файл в UI Obsidian |

## Отношение к Graphify

Graphify может экспортировать граф в Obsidian через `graphify export obsidian --graph <checkout>/graphify-out/graph.json --dir <явно-выбранный-vault>`. Это отдельная возможность `graphify`: экспорт выполняется по запросу пользователя и требует записи в указанный vault. Для работы с обычными заметками Graphify не требуется.
