# Переход с v0 на общий ADC

Результат — один общий контейнер ADC для всех подключённых проектов. Старые devcontainer служат источниками данных для миграции и остаются остановленными. Миграция копирует данные в новые тома; исходные каталоги, контейнеры и тома не удаляются.

Все команды выполняйте на хосте; в WSL — внутри того дистрибутива, где работал старый ADC. Следующий шаг выполняйте только после успешного завершения предыдущего. Имена контейнеров и ID профиля в примерах замените своими.

## 1. Остановить старую среду

Сохраните работу в редакторе, завершите сессии агентов и посмотрите имена старых контейнеров:

```sh
docker ps -a --filter label=devcontainer.local_folder --format '{{.Names}}'
docker stop old-container
```

Остановите все контейнеры, использующие старую платформу или общий том инструментов. Контейнеры и тома не удаляйте.

## 2. Заменить установленный ADC

Получите исправленный updater из v0 в обычный каталог установки:

```sh
git -C "$HOME/.local/share/ai-devcontainer" fetch origin v0 &&
git -C "$HOME/.local/share/ai-devcontainer" switch --detach FETCH_HEAD
```

После успешного переключения:

```sh
adc update --branch main
```

Установка сохранит копию старой платформы, заменит ADC в PATH и настроит completion. Дополнительный каталог установки не нужен. Откройте новый терминал. Старые devcontainer пока не запускайте и не пересоздавайте; проекты через adc project add пока не добавляйте.

## 3. Скопировать и проверить данные

Укажите каждый старый контейнер отдельным флагом --container. План запишет ID профилей в containers[].project; один из них понадобится для --account при импорте.

```sh
adc migrate legacy plan --container old-container --output "$HOME/adc-migration-plan.json"
```

После успешного создания плана:

```sh
adc migrate legacy backup "$HOME/adc-migration-plan.json" --output "$HOME/adc-backup-v0" &&
adc migrate legacy verify "$HOME/adc-backup-v0"
```

Каталог adc-backup-v0 должен быть новым. Backup включает кеши и Docker-in-Docker: проверьте свободное место. Во время копирования не меняйте исходные файлы. Копия содержит секреты — храните её в личном каталоге.

## 4. Импортировать в одну новую среду

Выберите профиль, чьи аккаунты и настройки станут общими. В примере его ID — portal-frontend:

```sh
adc migrate legacy import "$HOME/adc-backup-v0" --account portal-frontend --workspace developer-v1 &&
adc workspace start
```

Импорт зарегистрирует все проекты из плана и скопирует данные в новые тома одной среды. Остальные профили сохранятся отдельно; истории и совместимые файлы сессий копируются без перезаписи конфликтов. developer-v1 — имя новой среды, пути установки остаются прежними.

Проверьте вход в агенты, старые сессии, MCP и Obsidian. Старые данные удаляйте только после проверки. Первый запуск доставит управляемые файлы ADC в существующие репозитории; DinD, проектные порты и расширения VS Code автоматически не переносятся.

Состав копии, установка на Windows, восстановление после прерывания и возврат к v0 — в [справке](migration-reference.md).
