# Поставка рабочей среды ADC

ADC подключает существующие репозитории к общей среде через `adc project add`. Команда `adc workspace start` запускает среду и доставляет инструкции и выбранные возможности. Контекст checkout также подготавливается перед запуском поддерживаемого агента и при изменении возможностей через `adc project capability add` или `adc project capability rm`.

- [Назначение, быстрый старт и команды](../README.md).
- [Установка и обновление](installation.md).
- [Настройки проектов, MCP, знания и миграция](workspace.md).
- [Архитектура платформы](../SPEC.md).

При переходе с проектных devcontainer проверьте новую среду и при необходимости импортируйте авторизации с резервной копией. ADC не удаляет прежние devcontainer-файлы из подключённых репозиториев.

## Версии единиц доставки

У каждого скилла и бандла есть `meta.json` в его каталоге. У каждого MCP есть `<имя>.meta.json` рядом с файлом его определения: общим `delivery/mcp/servers.json` или `mcp.json` внутри бандла. У каждого доставляемого документа и инструкции есть `<полное-имя-файла>.meta.json` рядом с исходником, например `delivery/instructions/AGENTS.platform.md.meta.json`. Все метафайлы имеют один формат:

```json
{
  "kind": "skill",
  "name": "humanizer",
  "version": "3.31.4-adc.1"
}
```

`kind` принимает `skill`, `mcp`, `bundle` или `document`; документы и инструкции используют `document`. Пара `kind/name` уникальна в поставке. `version` обозначает выпуск содержимого по SemVer. Поле `version: 1` в существующем `bundle.json` остаётся версией формата и не участвует в сравнении обновлений.

При изменении единицы повысьте её версию в метафайле. Для изменённого скилла, MCP, документа или инструкции внутри бандла повысьте также версию бандла. Локальные исправления импортированного скилла можно обозначать последовательными версиями `3.31.4-adc.1`, `3.31.4-adc.2`. Изменение содержимого без изменения версии не создаёт уведомление. Отдельного списка версий нет.

После публикации ADC получает эти метафайлы из tracking-ветки платформы. Более высокая версия или новая единица появляется в `adc updates`; равная и более старая версия не предлагаются. Проверка ничего не применяет: это делает `adc update --delivery`, без пересборки образа и перезапуска контейнера. В работающей среде доставка применяется к подключённым проектам и их worktree сразу; в остановленной — при следующем запуске. Read-only проекты не изменяются. Полное обновление CLI, образа и инструментов среды выполняется командой `adc update` на хосте. Проектные форки сохраняют свои правила приоритета; наличие новой платформенной версии не означает автоматическую замену форка.

Обновление документов относится к файлам доставки ADC и управляемым блокам в инструкциях проекта. Например, ADC обновляет свой `AGENTS.platform.md`, сохраняя ручной текст в `AGENTS.md` и `CLAUDE.md`. Произвольные README, спецификации и другие документы самого проекта эта команда не переписывает.
